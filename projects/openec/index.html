OPENEC · 功能介绍 · 2026-10-25

一张日版 CD，
从东京卖到美国

OpenEC 是 eBay 美国站的代发运营台。店里的刊登在这里集中管理；每条刊登对应到 Amazon 日本站的一条具体卖家报价，再按定价规则算出售价。下面按使用顺序介绍现在能用的功能，最后讲接下来要做的。

全流程

一条刊登，从找货到每日维护要经过七站

图中轨道上的实心橙环是已经能用的功能，灰环是接下来要做的。CD 沿着轨道走，就是一条刊登在系统里的一生。

  • 同步刊登：把 eBay 店里的刊登读进来，统一管理。
  • 核对身份：确认每条刊登对应 Amazon 日本站的哪个商品（ASIN）。
  • 选报价：选定从哪个卖家的哪条报价进货。
  • 定价：按规则算出目标售价，算不出就写明原因。
  • 写回 eBay、每日维护、选品上架：接下来要做的三件事。

工作台 · 已可用

登录先看工作台，今天的待办一眼可见

用原来的账号和原样的登录页登录。工作台上全是真实数字，每个数字都能点进去直接处理。

  • 店铺状态：侧栏店铺卡显示 eBay 是否已连接。
  • 同步状况：在售刊登数和环形图（已同步 / 不同步 / 未找到 / 失败），点哪一段就跳到商品页的对应筛选。
  • 待办：待核对、待选报价、定价拦下的条数，点了直接去处理。
  • 数据隔离：每个客户只看得到自己店里的数据；平台管理员只做客户和用户管理，不碰经营数据。

环形图的比例只是示意，以系统里的真实数字为准。

商品 · 已可用

店里全部刊登，在一张表里查、筛、批量处理

图中每一块砖是一条刊登，颜色是类别。现在系统里有 147 条：CD 93、自动铅笔 22、美甲工具 19、DVD / 蓝光 10、其他 3。

  • 状态标签页：全部 / 待核对 / 待选报价 / 已绑定 / 已结束，各带条数。
  • 搜索与筛选：按 Item ID、标题搜索；按多级类别树、标签（同时包含 / 任一）、包装、生效规则、同步状态筛选。刷新页面后筛选和页码都不丢。
  • 批量操作：不限于当前页，可“选择全部符合筛选的 N 条”，批量加减标签、登入规则。
  • 商品详情：右侧滑出，左边是 eBay 原样详情（图组、变体、描述），右边是售价与同步状态、登入的规则、包装。
  • 立即同步：后台读取 eBay，进度可见，结束时报告新增 / 更新 / 失败。读不完整时不改任何数据，也从不删除刊登。

核对 · 已可用

左边 eBay，右边 Amazon，一条一条确认是不是同一个商品

逐条核对页：左边是刊登，右边是 Amazon 候选，条码和型号一致或不一致都有明显标记。系统和 AI 只给提示，确认按钮由人来按。

像不像无法判断
  • 让 AI 看看：AI 比对两边的封面图和条码，给出判断和理由，结果显示在右下角浮窗。
  • 详细比对：标题、品牌、型号、条码、版本、成色、图片逐行对照，一致的标绿，不一致的标黄。
  • 四种处理：确认、改 ASIN、暂不绑定、排除错误候选，都在居中弹窗里完成。用 ← / → 切换刊登。
  • 找候选：没有建议的刊登，按条码、再按关键词去 Amazon 找。查询 Amazon 有每日额度，会先显示要用多少，不够就停下并说明原因。

选报价 · 已可用

从哪个卖家进货，由人来定

确认了对应哪个 ASIN 之后，再选进货的报价。图中每根柱子是一个卖家的报价，高度是价格加运费的合计。

  • 刷新报价：读取这个 ASIN 当前全部卖家的报价，按合计从低到高排列。
  • 不预选：最便宜的不一定是最合适的，系统从不自动选。
  • 未知就是未知：价格或运费读不到时显示“未知”，不当成 0，也不当成缺货。
  • 绑定：绑定到具体的卖家、成色和配送方式（FBA / FBM）。之后可以换，也可以取消；商品表的“来源”列显示卖家和合计。

柱子上的价格和卖家是示例。

定价规则 · 验收中

刊登先登入规则，再由优先级最高的那条定价

图中五层板是五个优先级。CD 从上往下落，停在它登入的、优先级最高的那一层，由那一层的规则定价。

  • 筛选只圈候选：规则按店铺、类别、包装、标签圈出符合条件的刊登；刊登要明确“登入”才归这条规则管。
  • 优先级：最高 / 高 / 普通 / 低。一条刊登可以登入多条规则，生效的是已启用规则里优先级最高的那条。
  • 自由定价兜底：每个客户有一条内置的自由定价，优先级最低，不调价。新同步进来的刊登默认在它下面。
  • 预览分三组：生效 / 不生效 / 未绑定。算不出价的逐条写原因，并给处理按钮：去核对、去选报价、设置包装、刷新汇率……
  • 即改即算：改参数时预览马上按新参数重算，不保存就不生效。

定价计算 · 验收中

照着现有的 Excel 定价表，每个数都能在页面上改

美国以外的买家走日本邮政，按实重计费；美国买家走橙联，按实重和体积重（长×宽×高÷8000）取大，另收美国运费，关税由卖家承担。运费表、包装、费用参数、汇率都在定价页里改。

售价按区间维护：成本上涨、利润跌破下限时，一次涨回目标；高于目标只提示降价空间；差额太小不改。汇率每天从欧洲央行参考汇率取一次，波动超过缓冲才换。上面的计算用的是简化演示参数（汇率 150、运费 $14、eBay 费率 14.9%、利润目标为进货价加运费的 100%、尾数 .99）。

下一步 · 写回 eBay 与每日维护

算出的价格，每天自动写回 eBay

定价验收通过后开做。到时候生效规则算出的目标售价就是 eBay 上的售价，由后台每天同步一次。

  • 开通改价权限：店铺重新授权一次，允许系统修改 eBay 上的价格和库存。
  • 先试点：只对指定的不超过 3 个商品手动改价、改库存，改完再从 eBay 查一遍，确认真的改对了。
  • 每日维护：试点稳定后，系统每天自动跑一次：先刷新太旧的报价，再按规则算价并写入 eBay。不会按过期的报价改价。
  • 缺货处理：货源确认缺货时，把 eBay 库存归零。
  • 失败可见：没改成功或改完对不上的条目记为失败，出现在工作台待办里。

再往后

选品上架，然后正式上线

选品

从找货到上架一条线按策略在 Amazon 日本站找货 → 挑进候选 → AI 写好英文刊登草稿 → 人工修改并审批 → 上架到 eBay → 自动纳入管理和维护。AI 只出草稿，不会自己上架。

上线

正式上线部署到云服务器长期运行，大家用网址直接登录使用。

排队

其他计划邀请同事加入的页面；显示同类商品在 eBay 上的在售价格，作为定价参考；刊登规模到 10 万条时，货源价格改为分层跟踪，只刷新变了价的商品。

待确认

  • 定价参数：“日版 CD”规则里的美国运费档、变动提醒线等是占位值，核算后再定。
  • 写权限：写回 eBay 前需要店铺负责人重新授权一次，第一次真实写入只放 3 个商品。
